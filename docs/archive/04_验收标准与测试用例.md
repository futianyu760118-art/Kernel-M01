# M01 Kernel 测试与验收规范

## G1 MVP 准入条件
- [ ] System Registry、模块边界、Object ID 和 Contract Pack 经 M00 批准。
- [ ] M07/M13/POMS 真正运行的环境已经连接，联调等级达到 L4。
- [ ] 有用户身份与岗位归属、Agent 关系、授权策略/版本、决策 trace、审计记录。
- [ ] 高风险 `REQUIRE_APPROVAL` 不直接放行。
- [ ] 无开放式默认管理员密钥，服务端强制鉴权，所有 P0 安全缺陷关闭。

| Case | 场景 | 预期 |
|---|---|---|
| TC01 | M07 入职绑定岗位 | POMS 查询到该岗位允许能力 |
| TC02 | M07 调岗 | 旧能力撤销，新能力经 M01 策略批准 |
| TC03 | M07 离职 | 人和所有代理主体拒绝请求 |
| TC04 | 重复事件相同 event_id | 幂等，不重复授权 |
| TC05 | 乱序旧事件 | 不得恢复已经撤销的权限 |
| TC06 | M13 子 Agent 调用父 Agent 高权限 | 拒绝，不做隐式继承 |
| TC07 | 禁止权限直接调用服务端 | 401/403 或 DENY，无业务副作用 |
| TC08 | 错误/缺失签名 | 401 拒绝 |
| TC09 | 跨 tenant_id 访问对象 | 403 或 DENY，审计可追踪 |
| TC10 | 过期 Token、重放 webhook | 拒绝和记审计 |
| TC11 | 数据导出/付款/生产控制高风险操作 | 无批准票据不得执行 |
| TC12 | 审计系统故障 | 依据风险等级 fail-closed / durable outbox，不丢关键证据 |
| TC13 | M01 中断及恢复 | 核心安全操作 fail-closed；恢复后规则一致 |
| TC14 | 高并发撤权与缓存 | 不出现旧权限窗口超出批准 SLA |
| TC15 | 审计关联 | 决策、访问、事件、证据有同一 trace/correlation_id |

# M01 Kernel 项目执行方案 / W01–W36

## 目标
统一 AEOS 体系的人员、岗位、组织、智能体、服务和设备的身份与访问控制，使各子系统不能绕开 M01 获取生产、资金、设备、敏感数据和导出权限；提供可证明的撤权、审计和高风险人工介入机制。

## G0 前置与架构基线（W01–W04）
- [ ] M00 确认 Module Mapping、System Registry、Data Ownership、Object ID、API/Event/Result/Evidence Pack。
- [ ] 明确 M01 Owner、M07/M13/POMS/EDP 技术对接人、测试责任人及产品责任人。
- [ ] 核实真实仓库 URL、commit、API 路由、鉴权与环境、角色权限和网络路径。
- [ ] 批准 M01 权威身份/岗位/策略事实与 M07/M13 的事件源边界。
- [ ] 冻结 DEV/TEST 环境与测试租户，不使用生产个人信息或生产密钥。

## W09–W16 G2/G3
- 多租户组织与角色域；PostgreSQL 持久化；服务端可信认证（OIDC/OAuth2），MFA 及密钥轮换。
- 权限缓存失效/撤销事件与一致性保证；M02 审计 Outbox、失败重试、补偿和事件版本。
- 授权覆盖资源/对象/字段/行为，租户边界负向测试并出具报告。

## W17–W28 G4–G6
- 接入业务自治中心、M13 多 Agent 工具授权、M14 开发身份、POMS 岗位 UI。
- 服务与设备身份、短期凭据、强制后端 PEP；高风险审批工单与一次性执行票据。
- 兼岗、多组织、岗位迁移、租户切换、执行/决策双层等典型业务验收。

## W29–W36 G7/G8
